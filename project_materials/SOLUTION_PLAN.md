## 1. 项目目标与总体策略

本项目包含三类任务：

1. **描述性与规律性分析**：理解两个地区的负荷分布、日内曲线、季节性和周周期；
2. **统计/机器学习建模**：通过 KMeans、回归和短期负荷预测模型提取规律；
3. **预测效果与规律性评价**：比较无气象模型与气象增强模型，并据此判断两个地区的可预测性。

整体原则：

- 严格按时间顺序处理数据，避免未来信息泄漏；
- Area1、Area2 分别建模，不强行使用同一模型；
- 所有模型先与简单基线比较，复杂模型只有在回测中明显更优才采用；
- 预测精度不只用一个指标评价，至少使用 MAE、RMSE、MAPE；
- 题目要求之外的扩展分析只用于增强证据，不替代题目要求；
- 所有图表、结果表、预测文件均保留可复现脚本。

# 3. 问题 1：2014 年负荷统计与负荷持续曲线

## 3.1 数据范围

提取：

- Area1：2014-01-01 至 2014-12-31
- Area2：2014-01-01 至 2014-12-31

每个地区应得到：

- 365 天
- 每天 96 个采样点
- 全年共 35,040 个 15 分钟负荷点

## 3.2 每日指标

对每天 96 点计算：

### 日最高负荷

```text
Daily_Max = max(96 points)
```

### 日最低负荷

```text
Daily_Min = min(96 points)
```

### 日峰谷差

```text
Peak_Valley_Diff = Daily_Max - Daily_Min
```

### 日负荷率

```text
Load_Factor = Daily_Mean / Daily_Max
```

日负荷率越接近 1，说明日内负荷越平稳；越低说明峰谷变化越明显。

## 3.3 分布分析

每个指标分别输出：

- mean
- median
- std
- min / max
- P5 / P25 / P75 / P95
- coefficient of variation（CV = std / mean）

图表：

1. 两地区日最高负荷箱线图；
2. 两地区日最低负荷箱线图；
3. 两地区日峰谷差箱线图；
4. 两地区日负荷率箱线图；
5. 对应直方图或 KDE 分布；
6. 月度均值变化图，用于判断季节性。

## 3.4 负荷持续曲线（Load Duration Curve）

方法：

1. 把 2014 年全部 35,040 个负荷值展开；
2. 从大到小排序；
3. 横轴使用持续时间比例或小时数；
4. 纵轴为 MW；
5. Area1 / Area2 绘制在同图对比。

同时可补充一张归一化持续曲线：

```text
Normalized_Load = Load / Annual_Max
```

以便比较“曲线形状”，而不是只比较绝对负荷规模。

## 3.5 两地区差异判断

重点比较：

- 峰值波动大小；
- 谷值稳定性；
- 峰谷差大小；
- 日负荷率高低及其波动；
- 月度季节性；
- 持续曲线陡峭程度；
- 工作日和周末曲线差异。

### 初步预测准确性判断逻辑

更可能被准确预测的地区通常应表现为：

- 日负荷曲线更相似；
- 峰值与谷值 CV 更低；
- 同一星期类型的曲线变化更小；
- 周周期更稳定；
- 极端异常日更少。

此处只做“初步预判”，最终结论将在问题 4–6 用真实回测误差验证。

# 4. 问题 2：KMeans 日负荷曲线聚类

## 4.1 样本构造

2014 年每天视为一个样本：

```text
X shape = 365 × 96
```

每行代表一天的完整 15 分钟负荷曲线。

Area1、Area2 分开聚类。

## 4.2 聚类前处理

需要防止负荷绝对规模主导 KMeans 距离。

因此测试两套方案：

### 方案 A：原始曲线标准化

对每一个时间点做 StandardScaler：

```text
各列 T0000 ... T2345 标准化
```

保留日负荷水平信息。

### 方案 B：日曲线形状归一化

每一天除以当天平均值或最大值：

```text
x_norm = x / mean(x)
```

主要识别“形状类型”。

最终采用：

- silhouette 更高；
- 聚类更稳定；
- 聚类中心更具有业务解释性

的方案。

## 4.3 聚类数选择

尝试：

```text
k = 2 ... 10
```

指标：

1. Silhouette Score —— 主指标；
2. Inertia / Elbow —— 辅助；
3. 不同随机种子下聚类稳定性；
4. 聚类规模是否过度失衡。

KMeans 推荐参数：

```python
KMeans(
    n_clusters=k,
    random_state=42,
    n_init=50
)
```

## 4.4 聚类结果解释

对每个 cluster：

- 绘制 cluster centroid；
- 绘制簇内典型日曲线；
- 统计星期一至星期日占比；
- 统计周末比例；
- 与天气中的温度/湿度/降雨关联；
- 比较季节月份分布。

聚类名称不预先强行指定。

只有数据证据支持时，才命名为例如：

- 正常工作日；
- 周末/低负荷日；
- 夏季高负荷日；
- 冬季高负荷日；
- 特殊波动日。

## 4.5 输出

- `k vs silhouette` 曲线；
- 最优 k；
- 聚类中心曲线；
- 每日 cluster 标签表；
- cluster × weekday/月度统计表；
- 两地区聚类稳定性比较。

聚类结果将在问题 4/5 中作为可选分类特征。

# 5. 问题 3：负荷与气象因素回归分析

## 5.1 时间范围

使用：

```text
2012-01-01 至 2014-12-31
```

原因：该区间同时拥有负荷和气象数据。

## 5.2 负荷响应变量

每天计算：

- Daily_Max_Load
- Daily_Min_Load
- Daily_Mean_Load

三个指标分别建模。

## 5.3 气象自变量

基础变量：

- 最高温度
- 最低温度
- 平均温度
- 相对湿度
- 降雨量

### 扩展变量（用于验证非线性，不替代基础分析）

- 日温差 = Tmax - Tmin
- 是否降雨 = Rain > 0
- 平均温度平方项 `Tavg²`

温度与负荷可能并非线性关系，因此如果残差图显示明显弯曲，将加入温度二次项。

## 5.4 分析顺序

### Step 1：相关性分析

分别计算：

- Pearson correlation
- Spearman correlation

并绘制相关性热图及负荷-天气散点图。

### Step 2：单变量回归

对每个天气因素单独做线性回归：

```text
Load = β0 + β1 × Weather
```

目的：理解单一变量解释力。

### Step 3：多变量回归

```text
Load = β0 + β1*Tmax + β2*Tmin + β3*Tavg
       + β4*Humidity + β5*Rain
```

检查：

- R² / Adjusted R²
- MAE
- RMSE
- MAPE
- 残差分布
- 多重共线性

温度三变量高度相关时，不仅看 p-value，还要看 VIF 与模型增量效果。

### Step 4：时间外验证

不使用随机打乱切分。

推荐：

```text
Train: 2012–2013
Test : 2014
```

这样更接近真实预测环境。

## 5.5 天气变量推荐标准

最终优先推荐天气变量时，不只看相关系数，而综合：

1. 与负荷关系稳定；
2. 具有明确物理/业务解释；
3. 加入模型后 2014 年测试误差下降；
4. 在 Area1、Area2 是否均有效；
5. 在峰值负荷时段是否特别有效。

最终推荐可能不同地区不同，不预设结论。

# 6. 问题 4：不使用气象因素的 2015-01-04 至 2015-01-10 负荷预测

## 6.1 预测目标

每个地区预测：

```text
7 天 × 96 点 = 672 个负荷值
```

输出：

- `Q4_Area1_Load.csv`
- `Q4_Area2_Load.csv`

## 6.2 重要建模原则

该题属于严格时间序列预测。

必须确保模型在预测某一天时只使用当时实际可获得的信息。

尤其注意：

- 2015-01-04 之后的实际负荷未知；
- 不允许直接使用未来一天真实 `lag_1d`；
- 使用递归预测时，后续日只能使用前面预测值，而不能用真实值。

## 6.3 基线模型

必须先建立简单基线：

### Baseline A：上周同日同时间

```text
Prediction(t) = Load(t - 7 days)
```

### Baseline B：过去 4 个相同星期类型平均

例如预测星期一 09:00：

```text
过去 4 个星期一 09:00 平均值
```

### Baseline C：加权周周期

```text
0.4 × lag_7d
+ 0.3 × lag_14d
+ 0.2 × lag_21d
+ 0.1 × lag_28d
```

简单模型是判断高级模型是否真正有价值的基准。

## 6.4 机器学习模型

首选树模型：

- XGBoost / Gradient Boosting
- Random Forest 作为辅助对照

提供的参考资料强调了 XGBoost 在负荷预测中结合特征工程、参数调优和滚动验证的思路，因此将其作为主要候选模型。

## 6.5 无天气特征

### 时间特征

- month
- day_of_week
- weekend
- day_of_year
- 15-minute slot（0–95）
- slot 的 sin/cos 周期编码

### 历史负荷特征

优先使用不会产生未来泄漏的：

- lag_7d
- lag_14d
- lag_21d
- lag_28d
- 相同时间点过去数周均值
- 相同星期类型历史均值
- 上周同日 Daily_Max / Mean / Min

### 聚类标签

问题 2 的日类型 cluster 可作为可选特征。

## 6.6 两种预测架构

### 架构 1：固定周期滞后模型

只使用 7 天及更长滞后。

优点：

- 预测 7 天时不发生递归误差；
- 训练和正式预测逻辑一致。

### 架构 2：递归模型

加入 lag_1d / lag_2d 等近期特征：

- Jan 4 用真实 Jan 3；
- Jan 5 开始使用 Jan 4 的预测；
- 误差可能逐日累积。

通过历史滚动回测决定是否采用。

## 6.7 时间序列滚动回测

模型不能用随机 train/test split。

采用 rolling-origin 7-day backtest。

例如在 2014 年选择多个预测起点：

```text
训练数据：预测起点之前全部历史
验证窗口：之后连续 7 天
```

重复 8–12 个窗口。

每个地区、每个模型计算：

- MAE
- RMSE
- MAPE
- 每日 MAPE
- 峰荷时段 MAPE

最终模型由历史回测决定，而不是凭经验选。

## 6.8 在没有真实 2015-01-04~10 负荷时如何评价可信度

用历史回测误差分布给出推断：

例如：

```text
Median MAPE
P75 MAPE
P90 MAPE
```

再检查预测结果：

- 是否出现负值；
- 是否突然跳变；
- 峰谷时间是否合理；
- 日际变化是否超出历史范围；
- 与前几周同星期曲线是否明显冲突。

最终给出“高/中/低置信度”及理由。

# 7. 问题 5：加入天气因素重新预测

## 7.1 目标

预测区间仍为：

```text
2015-01-04 至 2015-01-10
```

气象数据已经覆盖这一时段。

输出：

- `Q5_Area1_Load.xlsx`（若最终交付要求必须 Excel）
- `Q5_Area2_Load.xlsx`

GitHub 项目内部可同时保留 CSV 版本便于版本控制。

## 7.2 公平比较设计

为了判断天气是否真的带来提升，必须做同样的数据窗口和同样模型结构的 A/B 比较：

### Model Base

```text
Calendar + Historical Load
```

### Model Weather

```text
Calendar + Historical Load + Weather
```

二者：

- 相同训练日期；
- 相同验证窗口；
- 相同超参数搜索范围；
- 相同评价指标。

这样模型差异才能归因于天气变量。

## 7.3 加入的天气特征

基础：

- Tmax
- Tmin
- Tavg
- Humidity
- Rainfall

扩展：

- temperature range
- rain indicator
- Tavg²

树模型可自动学习天气与时段的非线性交互。

## 7.4 评估天气是否有效

主要证据：

```text
ΔMAPE = MAPE_base - MAPE_weather
ΔRMSE = RMSE_base - RMSE_weather
```

并按场景分组：

- 高温日
- 低温日
- 高湿日
- 降雨日
- 日间高负荷时段
- 夜间低负荷时段

如果天气模型只在极端天气明显提升，也应明确写出，而不是简单说“整体有效”。

## 7.5 注意事项

当前天气数据是“日尺度”，而负荷是 15 分钟尺度。

因此天气模型可以改善“日负荷水平”，但对精确的日内温度变化捕捉有限。

这会作为结果解释中的重要局限性。

# 8. 问题 6：两地区整体规律性评价

问题 6 不只复述问题 1，而要用多个证据交叉验证。

计划建立以下证据体系。

## 8.1 日/周自相关

计算负荷时间序列 ACF：

```text
lag = 96     → 1 天
lag = 672    → 7 天
```

周周期相关性越高，一般说明规律性越强。

## 8.2 同星期曲线相似度

对于同一星期类型的日曲线，计算：

- Pearson correlation
- cosine similarity
- normalized RMSE

例如比较不同星期一之间的曲线。

## 8.3 KMeans 聚类质量

使用问题 2 的：

- 最佳 silhouette；
- cluster 内离散度；
- cluster 稳定性。

聚类更清晰通常说明负荷存在更稳定的日类型结构。

## 8.4 统计波动性

比较：

- 日最大负荷 CV
- 日最小负荷 CV
- 峰谷差 CV
- 日负荷率 CV

## 8.5 周期频谱（增强证据）

通过 FFT / periodogram 检查：

- 1-day 周期；
- 7-day 周期。

周期峰越集中，周期规律越明显。

## 8.6 最重要证据：真实历史预测误差

问题 4/5 的 rolling backtest 将成为规律性评价的核心证据。

若某地区在多种模型、多个验证窗口中：

- MAPE 始终更低；
- 误差标准差更小；
- P90 error 更低；

则可以较有力地判断其整体规律性和可预测性更强。

## 8.7 最终规律性评分表

最终整理：

| Evidence | Area1 | Area2 | Better |
|---|---:|---:|---|
| Daily variability | | | |
| Weekly autocorrelation | | | |
| Daily-curve similarity | | | |
| KMeans silhouette | | | |
| Q4 backtest MAPE | | | |
| Q5 backtest MAPE | | | |
| Forecast error stability | | | |

结论必须由上述数据共同支持。

# 9. 模型评价指标

## MAE

```text
MAE = mean(|y - ŷ|)
```

优点：直观、稳健。

## RMSE

```text
RMSE = sqrt(mean((y - ŷ)^2))
```

对大误差处罚更重。

## MAPE

```text
MAPE = mean(|(y - ŷ) / y|) × 100%
```

适合两个不同负荷规模地区横向比较。

由于负荷正常情况下明显大于 0，MAPE 可作为主要指标。

### 建议主要排序

```text
1. MAPE
2. RMSE
3. MAE
```

并报告误差分布而不只报告平均值。

# 10. 防止数据泄漏的规则

整个项目严格遵守：

1. 标准化器只在训练集 `fit`；
2. KMeans 用于预测特征时，只允许使用历史可得到的信息；
3. 回归/预测验证使用时间切分；
4. 不随机打乱时间序列做最终模型评估；
5. 2015-01-04 之后真实负荷不得进入 Q4/Q5 模型输入；
6. 超参数调优只在历史 backtest 上进行。

# 13. 实施顺序

## Phase 0 — 数据整理

1. 读取四个 CSV；
2. 日期解析；
3. 异常检查；
4. Area2 异常负荷修复；
5. Area1 weather 缺失处理；
6. 保存 clean 数据缓存和 audit log。

## Phase 1 — Q1

完成 2014 统计分析和持续曲线。

**这一步会给出第一个“哪个地区更好预测”的初步假设。**

## Phase 2 — Q2

KMeans 聚类并确定日负荷类型。

## Phase 3 — Q3

天气回归，筛选真正有效的气象变量。

## Phase 4 — Q4

先建立 baseline，再建立 ML 模型；进行 rolling 7-day backtest，选择 Area1 / Area2 各自最佳模型；正式预测 2015-01-04~10。

## Phase 5 — Q5

在完全相同回测体系中加入天气特征，用 ablation 证明天气是否提升预测精度；生成第二组正式预测。

## Phase 6 — Q6 + 总结

用统计规律、聚类质量、自相关和预测误差综合判断两个地区的规律性。

# 14. 最终判断标准

整个项目的核心不只是得到 672 个预测数，而是建立完整证据链：

```text
负荷统计特征
        ↓
日曲线类型结构
        ↓
天气影响强度
        ↓
无天气预测表现
        ↓
天气增强后的误差改善
        ↓
两地区规律性 / 可预测性最终判断
```

只有当问题 1 的描述性结论、问题 2 的聚类结构、问题 3 的天气敏感性和问题 4/5 的历史回测结果相互一致时，才给出最终的 Area1 vs Area2 规律性结论。
